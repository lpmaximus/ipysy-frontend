# 📄 1. Contexto

O sistema iPYSY possui um Core Matemático formalizado, determinístico, auditável e juridicamente defensável, responsável exclusivamente por:

* agregação probabilística coletiva (IGCI)
* reputação dinâmica contínua
* decaimento por inatividade
* governança por níveis EVT
* limites explícitos de influência
* prevenção de superusuários

Com a evolução do produto, tornou-se necessário definir claramente os módulos de usuários e produtos comerciais do iPYSY, garantindo:

* escalabilidade de negócio
* monetização sustentável
* experiência positiva para usuários gratuitos
* separação clara entre consumo, operação e produção de inteligência
* preservação integral do Core Matemático

Este ADR documenta a decisão oficial de criação dos módulos de usuários e produtos, sem qualquer alteração no Core.

# 📄 2. Decisão

Ficam oficialmente definidos os seguintes produtos/módulos do sistema iPYSY:

* iPYSY Free — Usuário Observador
* iPYSY Premium — Usuário Operador Individual
* iPYSY for Business — Produto B2B Institucional, com os pacotes: Starter, Pro e Enterprise

Esses módulos são camadas de produto, experiência e entitlement, operando exclusivamente acima do Core iPYSY, que permanece congelado e inalterado em seus princípios de governança.

# 📄 3. Princípios Arquiteturais

**O Core Matemático é agnóstico a planos**

O Core não conhece tipo de usuário, plano comercial ou monetização.
O Core recebe previsões válidas e retorna atualizações de reputação e consenso.

**Produtos não alteram matemática**

Nenhuma equação, parâmetro ou função do Core é modificada por tipo de usuário.

**Entitlement governa capacidades**

O que cada usuário pode ver, fazer ou exportar é definido por políticas externas ao Core.

**Separação clara de papéis**

* Free: consome contexto
* Premium: prova competência
* Business: produz e catalisa inteligência

# 📄 4. Metodologia de Comentários e Interações Sociais

## 4.1 Princípios Gerais

Os comentários no iPYSY não são uma rede social aberta. Eles existem como uma camada de contexto qualitativo, complementar aos dados quantitativos do sistema.

Princípios fundamentais:

* Comentários não afetam diretamente o Core Matemático
* Comentários não alteram reputação matemática
* Comentários não são votos, previsões ou inputs probabilísticos
* Comentários existem para interpretação, debate e leitura de contexto
* Produção de inteligência estruturada ocorre via Insights Institucionais (Produto Business)

## 4.2 Tipos de Interação

**Comentário de Evento**

* Texto curto ou médio associado a um evento específico
* Pode conter opinião, leitura de contexto ou observação qualitativa

**Thread de Discussão**

* Respostas encadeadas a um comentário principal

**Reações Qualificadas**

* Upvote / relevância (não é like social)
* Utilizado apenas para ordenação de leitura

## 4.3 Governança dos Comentários

* Comentários são moderados por políticas internas
* Rate limits são aplicados
* Detecção de abuso é automática
* Comentários podem ser ocultados sem impacto no Core

# 📄 5. Definição dos Produtos

## 5.1 iPYSY Free (Usuário Observador)

Objetivo: Aquisição, formação de contexto, educação e liquidez informacional.

**Capacidades:**

* Acesso a todos os eventos públicos
* Visualização de probabilidades agregadas
* Histórico resumido
* Dashboard simples (KPIs agregados)
* Rankings (diário, semanal, mensal e histórico)
* Leitura de comentários públicos (read-only)
* Leitura de insights institucionais (read-only)
* Favoritar eventos
* Alertas básicos
* Visualização de score e nível EVT (sem acesso ao selo)
* Upsell dinâmico: exibe qual seria o selo no modo Premium

**Restrições:**

* Não cria comentários
* Não responde threads
* Dados com leve delay
* Sem simulações
* Sem exportação
* Sem selo de reputação (ver ADR-016)
* Sem criação de eventos
* Sem criação de insights
* 0 escudos de streak por mês

## 5.2 iPYSY Premium (Usuário Operador Individual)

Objetivo: Fornecer vantagem analítica individual e permitir comprovação pública de competência.

**Capacidades:**

* Dados em tempo real
* Dashboard avançado
* Histórico completo
* Simulações e cenários
* Backtesting
* Alertas inteligentes
* Rankings com destaque
* Métricas detalhadas de performance
* Geração de Selo de Reputação iPYSY com QR Code verificável (ver ADR-016)
* Exportação limitada e certificada
* Criação de comentários em eventos públicos
* Participação em threads de discussão
* 2 escudos de streak por mês

**Restrições:**

* Comentários não geram insights institucionais
* Comentários não alteram reputação matemática
* Não cria insights institucionais
* Não cria eventos
* Não influencia narrativa institucional
* Acesso à API não permitido

## 5.3 iPYSY for Business (Produto B2B)

Objetivo: Atuar como infraestrutura e catalisador de dados probabilísticos multi-domínio, permitindo produção, análise e distribuição de inteligência.

**Capacidades gerais:**

* Leitura e análise de todos os comentários públicos
* Uso de comentários como sinal qualitativo complementar

**Pacote Starter**

* Acesso ampliado a dados históricos
* Dashboards institucionais básicos
* Consumo avançado de insights
* Leitura de comentários públicos
* Criação limitada de eventos (sob políticas internas)

**Pacote Pro**

* Criação de insights institucionais
* Publicação de análises estruturadas
* Criação de eventos públicos e privados
* Dashboards avançados
* Métricas de impacto
* Integração via API

**Pacote Enterprise**

* Todos os recursos Pro
* API completa
* Webhooks
* Multiusuário (times)
* SLAs
* Exportação avançada
* Possibilidade de white-label (futuro)

> **Observação:** Empresas não utilizam comentários como mecanismo primário de publicação de inteligência. Comentários permanecem como camada social; produção oficial ocorre via Insights Institucionais. Todas as ações institucionais permanecem sujeitas aos limites de influência e governança definidos pelo Core.

# 📄 6. O que NÃO Muda

Este ADR explicitamente congela os princípios de governança do Core iPYSY, incluindo:

* Governança por níveis EVT (0—5)
* Limites explícitos de influência por nível (Wₘₐₓ)
* Cálculo do consenso coletivo IGCI
* Decaimento temporal por inatividade (γ = 0,97 por período de 30 dias)
* Prevenção de superusuários (saturação logarítmica)

> **As fórmulas específicas de cálculo de ΔR e acurácia foram atualizadas no CORE iPYSY v3.2. Os princípios de governança acima permanecem inalterados entre v3.1 e v3.2.**

# 📄 7. Consequências

## 7.1 Positivas

* Clareza total entre produto, engenharia e negócio
* Monetização escalável
* Proteção jurídica do Core
* Facilidade de evolução de UX e planos
* Separação limpa entre B2C e B2B

## 7.2 Trade-offs

* Necessidade de uma camada robusta de entitlement
* Maior disciplina arquitetural
* Documentação adicional (ADRs e PRDs)
