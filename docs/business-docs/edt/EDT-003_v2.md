# 📄 Introdução

A iPYSY nasce com uma ambição clara: construir uma infraestrutura global de reputação baseada na acurácia de previsões verificáveis. Em um ambiente informacional saturado por opinião, ruído e polarização, a iPYSY adota um princípio simples e exigente:

**"Previsões devem ser objetivas, mensuráveis e verificáveis por fontes públicas confiáveis."**

Este Manual Editorial estabelece os critérios que orientam a criação, publicação e resolução de contratos na plataforma. Ele define limites, responsabilidades e compromissos que garantem neutralidade, segurança institucional e consistência internacional.

# 📄 1. Nossa Missão Editorial

## 1.1 O que a iPYSY é

* Sistema reputacional baseado em acurácia previsional
* Infraestrutura de consenso verificável
* Plataforma internacional de análise preditiva

## 1.2 O que a iPYSY não é

* Casa de apostas
* Exchange financeira
* Plataforma de investimento
* Mercado de derivativos
* Sistema de negociação entre usuários

A plataforma não permite remuneração financeira por acerto de previsão. O ativo central da iPYSY é a credibilidade do processo editorial e de resolução.

# 📄 2. Princípios Fundamentais

## 2.1 Objetividade

Toda previsão deve ser formulada de maneira inequívoca. Perguntas devem permitir resposta clara, binária ou quantitativa. Não são publicadas formulações subjetivas, interpretativas ou opinativas.

| **Tipo**    | **Exemplo**                                              |
| ----------- | -------------------------------------------------------- |
| Aceitável   | O PIB do país X no segundo trimestre será superior a 1%? |
| Inaceitável | O governo terá um bom desempenho econômico?              |

## 2.2 Verificabilidade

Cada contrato deve indicar obrigatoriamente:

* Fonte primária oficial
* Instituição responsável pela publicação dos dados
* Critério técnico de resolução
* Data definida de encerramento

Sem fonte confiável e rastreável, o contrato não é publicado.

## 2.3 Neutralidade Editorial

A iPYSY não adota posições políticas, ideológicas ou culturais. A formulação das previsões deve:

* Evitar linguagem emocional
* Evitar enquadramentos partidários
* Evitar adjetivações
* Evitar indução interpretativa

Neutralidade não é ausência de rigor — é compromisso com critérios públicos e verificáveis.

## 2.4 Princípio de Não-Dano

A plataforma não explora sofrimento humano. Não são publicadas previsões relacionadas a:

* Mortes individuais identificáveis
* Tragédias com vítimas diretas
* Conflitos armados em curso
* Doenças envolvendo vítimas individuais
* Eventos de violência ativa
* Questões étnicas ou religiosas sensíveis

A integridade humana prevalece sobre qualquer potencial de engajamento.

# 📄 4. Classificação Temática

## 4.1 Categoria A — Publicação Regular

Contratos nesta categoria seguem fluxo de publicação automático após validação técnica.

* Indicadores econômicos oficiais
* Resultados esportivos
* Estatísticas climáticas
* Resultados corporativos públicos
* Premiações culturais

## 4.2 Categoria B — Publicação com Revisão

Requer revisão editorial adicional antes da publicação.

* Eleições formais
* Reformas legislativas
* Decisões judiciais institucionais
* Eventos geopolíticos estruturados

## 4.3 Categoria C — Não Publicável

Contratos nesta categoria são vetados em qualquer jurisdição.

* Eventos com vítimas identificáveis
* Situações de sofrimento humano direto
* Criminalidade ativa
* Eventos com alto risco de dano social

# 📄 5. Matriz Global de Risco Editorial

Todos os contratos passam por avaliação estruturada de risco antes da publicação. O score é calculado com base nos fatores abaixo:

| **Fator de Risco**               | **Peso** |
| -------------------------------- | -------- |
| Tema político                    | +3       |
| Polarização histórica no país    | +3       |
| Risco regulatório local          | +4       |
| Evento institucional formal      | -2       |
| Fonte oficial pública            | -3       |
| Evento internacional padronizado | -2       |

## 5.1 Interpretação do Score

| **Score**         | **Ação**                                                   |
| ----------------- | ---------------------------------------------------------- |
| Score ≤ 0         | Publicação automática                                      |
| Score entre 1 e 4 | Revisão regional obrigatória                               |
| Score ≥ 5         | Revisão global obrigatória — Head Editorial + Compliance |

O score deve ser registrado internamente para fins de auditoria.

# 📄 6. Linguagem Institucional

## 6.1 Termos Proibidos

Não são utilizados termos associados a apostas, jogos ou investimento financeiro:

| **Termo Proibido**         | **Motivo**                              |
| -------------------------- | --------------------------------------- |
| Bet / Apostar / Apostar em | Associação direta com apostas           |
| Gamble                     | Associação com jogos de azar            |
| Invest / Investir          | Associação com instrumentos financeiros |
| Trade / Negociar           | Associação com mercados financeiros     |
| Odds                       | Terminologia de apostas                 |
| Payout / Ganho             | Implicação de recompensa financeira     |

## 6.2 Terminologia Oficial

| **Termo Oficial**     | **Contexto de Uso**                 |
| --------------------- | ----------------------------------- |
| Prediction / Previsão | Formulação de contratos             |
| Forecast / Projeção   | Análise prospectiva                 |
| Probability signal    | Indicador de consenso da plataforma |
| Consensus / Consenso  | Resultado agregado de previsões     |
| Accuracy / Acurácia   | Métrica de desempenho do previsor   |
| Reputation score      | Pontuação reputacional do usuário   |

A linguagem protege o posicionamento institucional e mitiga riscos regulatórios em todas as jurisdições.

# 📄 7. Processo de Publicação

| **Etapa** | **Ação**                              | **Responsável**                   |
| --------- | ------------------------------------- | --------------------------------- |
| 1         | Estruturação via template padronizado | Curador / Equipe Editorial        |
| 2         | Aplicação da Matriz de Risco          | Sistema / Editor Regional         |
| 3         | Revisão conforme score obtido         | Editor Regional ou Head Editorial |
| 4         | Registro interno da decisão           | Sistema de Governança             |
| 5         | Publicação na plataforma              | Sistema Automatizado              |

# 📄 8. Processo de Resolução

A resolução segue exclusivamente o critério técnico previamente definido no momento da publicação. Não é permitida interpretação retrospectiva.

| **Etapa** | **Ação**                              | **Responsável**       |
| --------- | ------------------------------------- | --------------------- |
| 1         | Verificação na fonte oficial indicada | Sistema / Editor      |
| 2         | Registro documental interno           | Sistema de Governança |
| 3         | Publicação do resultado               | Sistema Automatizado  |
| 4         | Atualização do histórico reputacional | Core Math v3.2        |

Resoluções não são alteradas retroativamente, exceto em caso de erro comprovado, documentado e aprovado pelo Head Editorial.

# 📄 9. Estrutura Internacional

A expansão para novos países exige cumprimento das seguintes etapas antes do lançamento:

* Mapeamento regulatório prévio pela equipe de Compliance
* Lista oficial de fontes locais confiáveis
* Ajuste da Matriz de Risco ao contexto nacional
* Monitoramento pós-lançamento nos primeiros 90 dias

Cada país opera sob módulo próprio de governança regional, subordinado ao Núcleo Global.

# 📄 11. Transparência e Auditoria

A iPYSY mantém os seguintes registros permanentes:

* Documentação das fontes de verificação
* Log interno de decisões de risco editorial

Confiança institucional depende de consistência operacional. A auditabilidade é um valor fundacional da plataforma.

## Implementado (event-service 9004, commit b75063b)

**Migration V65__Event_Editorial_Risk_Score.sql** — novos campos na tabela `events`:
- `source_url VARCHAR(500)` — URL da fonte primária (obrigatório)
- `resolution_criterion TEXT` — critério técnico de resolução (obrigatório)
- `country_reference VARCHAR(10)` — país de referência (obrigatório)
- `editorial_risk_score INTEGER NOT NULL DEFAULT 0` — score calculado automaticamente
- `risk_review_level VARCHAR(20) NOT NULL DEFAULT 'AUTO'` — nível: AUTO / REGIONAL / GLOBAL

**`EditorialRiskCalculator`** (`@ApplicationScoped`):
- Pesos exatos conforme seção 5: político+3, polarização+3, regulatório+4, institucional−2, oficial−3, internacional−2
- `reviewLevel(score)`: ≤0→AUTO, 1–4→REGIONAL, ≥5→GLOBAL
- `isCategoryBlocked(category)`: Categoria C → rejeição imediata (`EDITORIAL_BLOCKED`)

**`EventService.createEvent()`** — validações obrigatórias:
- `source_url` ausente → HTTP 400 `SOURCE_URL_REQUIRED`
- `resolution_criterion` ausente → HTTP 400 `RESOLUTION_CRITERION_REQUIRED`
- `country_reference` ausente → HTTP 400 `COUNTRY_REFERENCE_REQUIRED`
- Categoria C → HTTP 400 `EDITORIAL_BLOCKED` (antes do cálculo de score)
- Score calculado e persistido; eventos com revisão regional/global → status `ACKNOWLEDGED` + log WARN `[EDITORIAL_REVIEW]` para SigNoz

**`EditorialRiskCalculatorTest`** — 21 testes unitários (todos passando):
- `CategoryBlockedTests` (5 testes)
- `CalculateScoreTests` (10 testes)
- `ReviewLevelTests` (6 testes)
